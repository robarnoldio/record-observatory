- [ ] Decide: enrich album pages (cover art, tracklist, credits). Findings so far, no code written:
  - **Discogs API** (personal token in an env var): 60 requests/min authenticated, 25 unauthenticated, unique User-Agent required, so about 22 minutes for the ~1,230 releases once, then only new release IDs (cache per release). A release returns `tracklist` (position, title, duration), `artists` and `extraartists` (credits with roles), `labels` with catnos, `formats`, `genres`, `styles`, `notes`, `country`, `identifiers` (barcode), `master_id`, `videos` (YouTube). Drop marketplace/community fields (`lowest_price`, `num_for_sale`, `community`); they look like restricted data. Image URLs from the API are `api.discogs.com/<hash>/…` paths that return 404 without a token, so they cannot be hotlinked; covers would have to be downloaded and re-served. The API Terms limit caching/storing content longer than necessary, say not to show content over six hours stale, and restrict some data; read them before publishing stored Discogs data (the Terms page returned 403 to my fetch, so the wording is unverified).
  - **MusicBrainz + Cover Art Archive** (no key, ~1 request/sec, about 45-60 minutes for a full run): a Discogs release URL looks up an exact MusicBrainz release when someone linked them (`/ws/2/url?resource=https://www.discogs.com/release/ID&inc=release-rels`); `coverartarchive.org/release/<mbid>/front-250` (or `/release-group/<id>/front-250`) is a plain image with CORS open, so the site can store URLs and host nothing. Probe of 40 albums (stratified by decade and the five wanted labels): cover available for 30 (75%): 12 exact links (0 title mismatches; 9 with art on the exact pressing, 1 at release-group level, 2 without art), 20 found by artist+title search, 8 not found (compound artist credits like "A - B", "No Artist", classical/compilations). The five wanted labels were 10 of 10; undated albums 1 of 5. One false positive among the 20 searches (our "Keith Jarrett - Concerts" matched "Sun Bear Concerts" because the test allowed substring containment). Albums here are release groups in MusicBrainz terms, so album-level art fits the model.
  - **Planned matching rules** (borrowed from how beets scores candidates): exact Discogs-URL link first; otherwise a scored match on normalized title (equality, not containment), artist overlap (use `artist-groups.json` short names), year, label/catalog number, country and format, and track-title overlap between the Discogs tracklist and the candidate's tracklist; accept above a threshold, queue the middle for review, reject below. Cover order: exact pressing, then release group, then a text-art placeholder in the site's idiom. Keep an overrides file (release ID to MBID or cover URL). Cache match status and cover URLs, never images. Run as a Node script, resumable and incremental.
  - **beets considered and not adopted:** it is built around audio files on disk, `fetchart` writes image files rather than URLs, its extra art sources (iTunes, Amazon) mean re-serving commercial artwork, and it adds a Python toolchain plus an export step. Borrow its multi-field scoring instead.
  - **New angle: the FLAC library.** The user curates a FLAC library (files arrive well tagged with embedded cover art) served from an mpd database on more than one moOde server. Coverage is strongest for curated artists (Led Zeppelin, Miles Davis); weird records and classical could just get placeholders. A mostly programmatic LP-to-FLAC match (artist + album, or MusicBrainz IDs if the tags carry them) could supply covers, tracklists with durations and an "also on FLAC" flag, and would avoid the Discogs terms questions for images. To settle: do the FLAC tags carry MusicBrainz IDs; read via the mpd protocol or by scanning files (ffprobe/metaflac); where the script runs (it needs access to the library or an mpd server); extracting resized thumbnails into the repo versus linking Cover Art Archive; and keeping hostnames and file paths out of the published site. Possible phasing: (1) FLAC match for tracklists and covers, (2) MusicBrainz/Cover Art Archive for the rest, (3) Discogs API only for what both miss (credits, pressing notes, genres/styles).
